A WhatsApp-like system is a distributed, real-time, fault-tolerant messaging system that ensures low latency delivery, ordering, and reliability at massive scale (millions of concurrent users). I

Core components
API Gateway → auth, routing, rate limiting
Chat servers → maintain WebSocket connections
Message queue → async delivery (Kafka/RabbitMQ)
Database → store chats (NoSQL preferred)
Presence service → online/offline status

2. Mav sends "Hi"

```text
Mav App
  |
  |-- Send "Hi" -------------------------> Payload: {msgID, chatID, msg, ts}
  v
Chat Server A (Node.js / Netty / Go)
  |
  |-- Auth check ------------------------> JWT validation
  |-- Rate limit ------------------------> Redis (INCR + EXPIRE)
  |-- Assign ordering -------------------> Kafka partition (chatID key)
  |-- Publish ---------------------------> Async, non-blocking
  v
Kafka (Distributed Queue)
  |
  |-- Consume ---------------------------> Chat Server B (consumer group)
  v
Chat Server B (Horizontally scaled)
  |
  |-- Lookup Tom ------------------------> Redis (userID → serverID)
  |-- Check presence --------------------> Redis (online/offline)
  |-- If online -------------------------> Push via WebSocket
  |-- If offline ------------------------> Store in DB
  v
Tom App
  |
  |-- Display "Hi"
  |-- Send ACK --------------------------> Delivery confirmation
