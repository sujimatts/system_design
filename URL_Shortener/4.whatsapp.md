A WhatsApp-like system is a distributed, real-time, fault-tolerant messaging system that ensures low latency delivery, ordering, and reliability at massive scale (millions of concurrent users). I

Core components
API Gateway → auth, routing, rate limiting
Chat servers → maintain WebSocket connections
Message queue → async delivery (Kafka/RabbitMQ)
Database → store chats (NoSQL preferred)
Presence service → online/offline status

2. 2. Mav sends "Hi"

[Mav App]
   |
   | (1) Send message {msgID, chatID, "Hi", timestamp}
   v
[Chat Server A]                         // Node.js / Netty / Go (event-driven)
   |
   | (2) Auth + Rate Limit             // JWT + Redis (INCR + EXPIRE)
   |
   | (3) Ordering                     // Kafka partition (chatID key)
   |
   | (4) Publish (async)
   v
[Kafka]                                // Topic: messages, partitioned
   |
   v
[Chat Server B]                         // Consumer instance (scaled horizontally)
   |
   | (6) Lookup user                  // Redis: userID → serverID
   |
   | (7) Check presence              // Redis (online/offline)
   |      ├── Online → push via WebSocket
   |      └── Offline → store in DB
   v
[Tom’s Chat Server]
   |
   | (8) Push via WebSocket
   v
[Tom App]
   |
   | (9) Display "Hi"
   |
   | (10) Send ACK
   v
[Chat Server B]
   |
   | (11) Update status              // Redis + async DB write
   v
[Storage]                             // Cassandra / DynamoDB
